# 常见问题

## 会删除文件吗？

不会。整理和查重清理都是移动或重命名文件；重复文件会被移动到 `重复文件/`，可通过历史页撤销。

## 为什么预览里的目标位置和原文件一样？

当文件已经位于目标分类文件夹时，程序不会生成多余的操作。重命名预览中，如果新名称与原名称相同，也不会出现在预览里。

## 执行时提示「目标位置已存在同名文件」怎么办？

这是安全保护：预览生成后，目标位置可能被其它程序创建了同名文件。程序会跳过该条操作并保留原文件，不会覆盖。重新扫描后再次生成预览即可。

## 查重的三种方式如何叠加？

勾选多项时，组内文件必须同时满足全部条件。例如同时勾选「文件名相似」和「大小接近」，只有名字相似且大小差距在容差内的文件才会成组。「字节相同」会先按大小分桶，再做前缀哈希和完整哈希确认。

## 哈希会读取整个文件吗？

只有同大小且前缀哈希相同的文件才会继续做完整哈希。大文件可能较慢，可在查重页调整「读盘线程」，或取消「字节相同」只做名称 / 大小初筛。

## 为什么扫描不到某些文件？

- 默认跳过以 `.` 开头的文件，以及 Windows 隐藏属性的文件 / 文件夹；勾选「包含隐藏文件」可包含。
- `.file_organizer_logs/` 是撤销日志目录，任何情况下都不会参与扫描。
- 文件被其它程序占用或权限不足时，可能无法读取 stat 或哈希。

## 设置保存在哪里？

`%APPDATA%\FileOrganizer\settings.json`。其中保存预览表显示字段和排序；删除后会恢复默认。

## 打包版为什么是一个文件夹？

程序使用 PyInstaller onedir 模式打包，体积比单文件版小、启动更快。分发时需要保留整个 `FileOrganizer` 文件夹，不能只复制 exe。

## 有长路径限制吗？

程序目前没有统一添加 `\\?\` 前缀，仍受 Windows 传统 260 字符路径限制。文件名组件会截断到 255 字符以内，但较深的目录层级仍可能导致操作失败；失败条目会保留在结果中，不会覆盖已有文件。

## 为什么撤销失败了？

撤销会校验日志中的源路径和目标路径都位于日志所在工作目录树内。若文件已被移动、原位置出现同名文件，或日志来自其它目录，该条会失败并在结果中说明原因。
